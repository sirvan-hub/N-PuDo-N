# Pudo-N delivery-code SMS gateway contract

The recipient delivery-code flow uses the existing `custody_transfers` ledger with
`transfer_type = HUB_TO_RECIPIENT`. The code is generated by the backend, stored
only as a salted SHA-256 hash, expires after 10 minutes, and is limited to five
verification attempts. The plaintext code is never returned by the API or written
to audit logs.

## Required configuration

Configure these backend environment variables only after selecting and validating
an SMS provider or an internal SMS gateway:

- `DELIVERY_CODE_SMS_URL`: HTTPS endpoint in production.
- `DELIVERY_CODE_SMS_TOKEN`: bearer token for that endpoint.

The backend sends an authenticated JSON POST:

```json
{
  "to": "registered-recipient-phone",
  "template": "pudo_delivery_code",
  "parcelId": "parcel-uuid",
  "transferId": "custody-transfer-uuid",
  "message": "Pudo-N delivery code: 123456. It expires in 10 minutes."
}
```

The gateway must return a 2xx response only after it has accepted the message for
delivery. A non-2xx response or network error expires the pending transfer and
returns an unavailable-service error; the API does not claim that an SMS was sent.

This is a generic gateway contract, not a claim that a particular SMS vendor is
already connected. Provider-specific authentication, request fields, delivery
receipts, retry policy, and local regulatory requirements must be confirmed before
production use. Never place the bearer token or plaintext OTP in logs or source
control.

## API flow

1. The authenticated recipient calls `POST /parcels/:id/request-delivery-code`.
2. The backend verifies parcel ownership, READY_FOR_CUSTOMER state, and a PAID invoice.
3. The hub owner calls `POST /parcels/:id/confirm-customer-release` with
   `deliveryCode` and optional `nationalId`.
4. If the recipient has a national ID stored in their account, a supplied ID must
   match it. If no reference national ID exists, only the last four digits of a
   supplied ID are recorded in audit metadata; this is not treated as independent
   proof of identity.
5. A successful one-time verification marks the custody transfer CONFIRMED and
   the parcel COLLECTED in one database transaction and writes an audit event.

No Production configuration or SMS provider was changed by this PR.
